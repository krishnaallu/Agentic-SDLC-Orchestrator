# Agentic Engineering Orchestrator

Java 21 and Spring Boot prototype for turning a natural-language engineering request into a persisted, reviewable task graph. The orchestrator is the product; the URL shortener is a requirement submitted to it, not an application silently generated by this service.

## Current slice

- Create a run for a greenfield, brownfield, or ambiguous request.
- Persist the request, scenario-aware DAG, run status, and audit events in PostgreSQL.
- Plan implementation, test, and documentation branches in parallel after architecture, then synchronize at release readiness.
- Pause the plan in `AWAITING_APPROVAL`; record a human approval or rejection and decision note.
- Make no code changes and run no generated commands. Approval currently records plan acceptance only.
- Use a deterministic planning adapter so local behavior is reproducible and needs no model credentials.

The workflow engine, real model provider, code artifact generation, isolated validation, execution retries/rollback, re-planning, authentication, and URL-shortener implementation are subsequent slices. This is a working foundation, not yet a production deployment.

## Run locally

Requirements: Java 21 or later, Maven, and Docker Compose.

```powershell
docker compose up -d postgres
mvn spring-boot:run
```

The API listens on port `8080`. Health is available at `/actuator/health`. Database connection settings can be overridden with `DATABASE_URL`, `DATABASE_USERNAME`, and `DATABASE_PASSWORD`.

## API

Create a greenfield plan:

```powershell
Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/runs `
  -ContentType 'application/json' `
  -Body '{"requirement":"Build a URL shortener with click analytics and expiring links","scenario":"GREENFIELD"}'
```

The response includes the run ID, task nodes and dependencies, status, and audit events. Use the returned ID to inspect the run or record a plan decision:

```powershell
Invoke-RestMethod -Method Get -Uri http://localhost:8080/api/v1/runs/<run-id>

Invoke-RestMethod -Method Post -Uri http://localhost:8080/api/v1/runs/<run-id>/decision `
  -ContentType 'application/json' `
  -Body '{"approved":true,"actor":"reviewer","note":"Plan accepted for implementation"}'
```

`scenario` accepts `GREENFIELD`, `BROWNFIELD`, or `AMBIGUOUS`. Requests are limited to 4,000 characters. A decision can be recorded only once per run.

## Validation

```powershell
mvn test
```

Tests use H2 and do not require Docker. Local application runs use PostgreSQL; the schema is managed by Flyway. The test suite covers context startup, task dependencies and synchronization, human approval, and audit recording.

## Architecture notes

- `PlannedAgent` is the provider boundary. `DeterministicPlanningAgent` supplies the reproducible first implementation.
- The service validates node uniqueness and dependency ordering before persisting a DAG.
- Runs, tasks, and audit events are separate relational records; decision changes are protected by optimistic versioning.
- High-impact work remains review-first. This first slice intentionally has no endpoint that writes generated code into the repository.
